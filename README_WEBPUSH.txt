СПЕЦНАЗ v2.83 — Web Push (VAPID) + серверная отправка

ЧТО ВКЛЮЧЕНО
- index.html: VAPID public key уже подключён к кнопке уведомлений.
- sw.js: принимает push и показывает системное уведомление.
- push-config.php: VAPID private/public keys, секрет запуска cron и настройки.
- push-subscribe.php: сохраняет Push API-подписки.
- push-lib.php: VAPID JWT (ES256) и шифрование Web Push (aes128gcm).
- push-cron.php: проверяет ленту через существующий proxy.php, обнаруживает новые ID и отправляет push подписанным устройствам.
- data/: состояние и подписки; закрыта через .htaccess на Apache.

УСТАНОВКА
1. Сделайте резервную копию сайта.
2. Загрузите содержимое архива в ту же папку сайта, где находится index.html. Не загружайте папку specnaz_work целиком — загрузите её содержимое.
3. Требуется HTTPS, PHP 8.0+ (рекомендуется 8.1+), расширение OpenSSL и cURL. proxy.php также требует cURL; DOM желателен, но есть regex fallback.
4. В push-config.php замените mailto:admin@example.com на свой действующий адрес.
5. Убедитесь, что папка data доступна PHP для записи и недоступна посетителям сайта. Apache применит data/.htaccess. Для Nginx настройте запрет доступа к /data/ или вынесите data_dir из публичного web-root.
6. На хостинге создайте Cron Job для запуска push-cron.php раз в минуту. Предпочтительный вариант — CLI:
   php /ABSOLUTE/PATH/TO/SITE/push-cron.php
   Если хостинг разрешает только URL-cron, вызывайте:
   https://ВАШ-ДОМЕН/push-cron.php?key=N3P-No1DPkJ43PKGb7cNk2oeYCSSSlMifVb8T5kgkgDcOLN3
   Не публикуйте этот URL. Секрет можно заменить в push-config.php.
7. Откройте PWA по HTTPS и нажмите «ВКЛЮЧИТЬ УВЕДОМЛЕНИЯ». Разрешите уведомления. Подписка будет отправлена на push-subscribe.php.
8. Запустите push-cron.php вручную один раз. Первый запуск запоминает уже существующие сообщения и намеренно не рассылает старую ленту. Следующие запуски отправляют уведомления о новых ID.

ПРОВЕРКА
- Откройте https://ВАШ-ДОМЕН/proxy.php — ожидается JSON с ok:true и messages.
- После разрешения уведомлений push-subscribe.php должен вернуть {"ok":true,"saved":true}.
- Запустите cron: ожидается JSON/CLI с ok:true. pushAccepted означает, что push-сервис принял запрос, а не гарантию отображения на каждом устройстве.
- Для теста опубликуйте/дождитесь нового сообщения источника и дождитесь очередного запуска cron.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
- На обычном shared hosting cron обычно запускается не чаще раза в минуту; поэтому фоновые push могут приходить с задержкой до интервала cron. Клиентская лента по-прежнему опрашивается каждые 5 секунд, пока приложение открыто.
- iPhone: для Web Push обычно требуется iOS/iPadOS 16.4+ и приложение, добавленное на экран «Домой»; разрешение запрашивается нажатием пользователя.
- Web Push требует работающих cURL/OpenSSL и исходящих HTTPS-запросов с сервера. На реальном хостинге надо проверить ответ push-сервиса.
- Push отправляется на каждое новое сообщение источника (не только high priority), без выдумывания сообщений. Первый cron-run не отправляет старые сообщения.
- Если push-cron.php возвращает feed_unavailable/no_messages_parsed, сначала исправьте доступность/структуру источника в proxy.php.
- VAPID private key и cron_secret хранятся только в push-config.php на сервере. Не отправляйте этот файл в публичный репозиторий.
