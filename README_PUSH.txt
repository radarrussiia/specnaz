СПЕЦНАЗ v2.82 — PROXY INTEGRATED

ЧТО ИЗМЕНЕНО
- Добавлен proxy.php: сервер запрашивает фиксированный источник https://parsertgtovknews.ru/max/map.php и возвращает JSON-ленту messages.
- Формат ответа: {"ok":true,"source":"...","fetchedAt":"...","count":N,"messages":[{"id":"...","text":"...","datetime":"...","timestamp":123,"priority":"high|normal"}]}.
- index.html уже опрашивает ./proxy.php каждые 5 секунд; клиентская интеграция сохранена.
- Service Worker больше не кэширует proxy.php, чтобы клиент получал свежий JSON.
- Версия приложения и кэш Service Worker обновлены до v2.82.

УСТАНОВКА
1. Сделайте резервную копию сайта.
2. Распакуйте архив и загрузите ВСЁ содержимое в папку сайта рядом с index.html. Убедитесь, что proxy.php находится в той же папке, что и index.html.
3. Сервер должен поддерживать PHP 8.1+ и расширение cURL; DOMDocument используется при наличии, иначе включается ограниченный HTML-парсер.
4. Откройте https://ВАШ-ДОМЕН/proxy.php в браузере. Должен вернуться JSON с ok:true и массивом messages. Если вернулась ошибка, прочитайте поле error/detail и проверьте журнал PHP-хостинга.
5. Откройте PWA, разрешите уведомления и проверьте появление нового сообщения после публикации нового поста у источника.
6. Если PWA показывает старую версию, полностью закройте приложение и откройте его снова.

ВАЖНЫЕ ОГРАНИЧЕНИЯ
- proxy.php извлекает опубликованные сообщения из HTML страницы источника. Это не внутренний API карты и не извлечение координат/маркеров карты.
- Опрос каждые 5 секунд работает, пока приложение открыто и страница активна. Браузер может приостановить фоновые таймеры.
- Настоящие системные Push-уведомления при закрытом PWA/заблокированном экране требуют отдельного сервера отправки Web Push, VAPID-ключей, сохранения push-подписок и периодического серверного задания. Этот архив НЕ содержит приватных VAPID-ключей и НЕ заявляет, что фоновая доставка уже настроена.
- Первое успешное получение ленты используется как исходная база: старые сообщения не должны массово показываться как новые. Далее уведомляются только сообщения с новыми ID.
- Если источник изменит HTML-разметку, endpoint вернёт no_messages_parsed, а не вымышленные данные.

БЕЗОПАСНОСТЬ
- Адрес источника фиксирован в proxy.php; произвольный URL из запроса не принимается.
- Ошибки upstream возвращаются как JSON с HTTP-кодом 502; детали не раскрывают секреты.

Для настоящего фонового Push потребуется отдельная настройка VAPID и серверного отправщика Web Push.
